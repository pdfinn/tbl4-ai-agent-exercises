# Bonus B4 — Check a Date, Else Find an Alternate

*Instructor-facing overview. Student-facing instructions are in `B4-a-blank.md` and `B4-b-half-built.md`.*

A standalone bonus exercise, requested as "check a date on a calendar; if unavailable, find an alternate (Monday or Tuesday afternoons)." It's the Ex 03/04 routing pattern applied to dates, and it introduces n8n's built-in date library, **Luxon** — no credentials, no real calendar.

## Learning goal

By the end students should:

- Use **Luxon** inside expressions: `DateTime.fromISO()`, `.weekday` (1–7), `.plus({ days })`, `.toFormat('yyyy-MM-dd' / 'cccc')`.
- Compute "the next Monday/Tuesday after a date" with `(8 - weekday) % 7 || 7` (and adapt 8→9 for Tuesday).
- Test array membership in an IF (`!busy_dates.includes(requested_date)`).
- Recognise the **gate-and-branch + converge** skeleton from Ex 03/04 in a new domain.
- Understand why `chosen_weekday` must be computed in a *later* node than `chosen_date` (a Set node can't read its own sibling assignments).
- Keep the rule: **dates computed in expressions, prose generated by the LLM.**

## Domain

A meeting-scheduling assistant. Inputs: `requested_date` and a `busy_dates` list (the stand-in "calendar"). The preference is "Monday or Tuesday afternoons." The fixture is rigged so the requested date *and* the next Monday are both busy, so the deterministic answer is the next Tuesday (`2026-06-09`).

## Why no real Google Calendar?

Same reasoning as the rest of the bonus set: a live calendar means OAuth or a Service Account, which is credential setup, not logic. The routing logic *is* the lesson, and it's identical whether the busy list comes from a Set node or a Calendar free/busy node. The extension shows the one-node swap.

## Why no loop (and no Code node)?

"Find the *next available* slot" genuinely wants a loop, and a clean loop in n8n means a Code node — off-limits this early. The exercise sidesteps it: compute exactly two candidates (next Mon, next Tue) and choose with a nested ternary. The `none` outcome (both taken) is the honest seam where you'd later introduce a loop. Mention this; don't paper over it.

## Recommended session flow (~40 min)

1. **(5 min) Recognise the skeleton.** Draw it next to Ex 03/04. "Same IF-and-converge shape. New: the predicate is a date test, and we compute dates with Luxon."
2. **(5 min) Luxon weekday demo.** In any Set node, show `{{ $now.weekday }}` and `{{ $now.toFormat('cccc') }}`. Land that Monday = 1.
3. **(20 min) Pair build.** Watch for the `{{ true }}` IF left in place (confirms busy dates), and for `chosen_weekday` wrongly placed in Pick Alternate.
4. **(5 min) Run all three outcomes** by editing `busy_dates` (table in `B4-c-reference.md`). This proves the routing routes.
5. **(5 min) Debrief.** The `none` case → "how would you search further?" → loops. The busy-list → Calendar swap → real-world.

## The 3 gaps in variant B (answer key)

1. **Compute Candidates → `cand_tue`** — Monday expression with `8`→`9`.
2. **Requested Date Free? → condition** — `={{ !$json.busy_dates.includes($json.requested_date) }}`, *is true*.
3. **Compose Reply → prompt** — branch on `status`; propose `chosen_date` (`chosen_weekday` afternoon) for `alternate`.

## Expected result

Requested `2026-06-03` and next Monday `2026-06-08` are both busy → proposes **Tuesday 2026-06-09**.

## Common student errors

| Error | Lesson |
|---|---|
| IF left at `{{ true }}` | Confirms busy dates. Test with a known-busy date. |
| `chosen_weekday` in Pick Alternate | A Set node can't read its own sibling field; it goes in Finalise. |
| LLM doing date maths | Wrong eventually. Compute in expressions. |
| Treats `weekday` as 0-based | Luxon: Monday = 1 … Sunday = 7. |
| Drops `\|\| 7` | Returns the same day when requested day already matches the target weekday. |
